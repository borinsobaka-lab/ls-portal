## 1. Что говорит бриф (коротко)

- Битрикс24 — основной рабочий инструмент: пользуются все 14 опрошенных,
  активно (50+ функций) — 7: эксперты ОР (Соня, Вера, Кристина, Вика),
  старший таргетолог, HR, главбух. Их ответы весят ×2.
- Рекомендация брифа: **MVP — 46 функций, этап 2 — 37, бэклог — 39, не
  делать — 55.** Ядро MVP: задачи (форма, роли, сроки, напоминания,
  чек-листы, шаблоны, регулярные, проверка, история), список с фильтрами,
  вид «Сроки», канбан, проекты отделов и городов, мессенджер (чаты, папки,
  упоминания, закрепы, файлы, поиск по всем чатам, гибкие уведомления),
  оргструктура и профили, роли доступа, перенос из Битрикс24.
- **Главные боли** (ради них всё и затевается):
  1. нет поиска по словам сразу по всем чатам (2.18, Д.1 — «нужно как в
     Telegram!!!», три человека);
  2. уведомления спамят и не настраиваются (1.7, 1.24, 2.26);
  3. чаты задач создаются автоматически и смешаны с обычными (1.19, Д.2);
  4. задача на нескольких исполнителей дробится на дубли (1.3);
  5. фильтр задач по дате создания, а не по сроку; закрытые висят сверху
     (1.30);
  6. нет деления прав партнёров и сотрудников УК (15.6);
  7. платформа тормозит, сообщения подгружаются не все (боль № 25).
- Вне портала: CRM, контакт-центр, почта, сайты. База знаний уже есть.
  Отдельно решить: карточки партнёров / сделки ОР (11.2–11.4) и календарь
  (4.2, 4.10 — P1 по опросу).

Отсюда три правила, которые проходят через весь план:

- **Тихо по умолчанию.** Уведомление — только когда от человека что-то
  нужно (ему поставили задачу, его упомянули, ему написали лично, его
  задача на проверке). Всё остальное — счётчики, а не пуши.
- **Поиск и скорость — не «потом», а с первого дня.** Это главное, чем
  портал должен выиграть у Битрикса.
- **Одна оргструктура и одни роли.** Задачи, чаты и справочник берут
  людей, подразделения, должности и права из того, что уже есть в
  «Пользователях и ролях» (ACCESS.md), а не заводят своё.

## 3. Структура и навигация

### 3.1. Рейка

Сейчас в рейке (на первом этапе): «Аналитика», «База знаний», «Академия»,
внизу «Управление». Добавляются три раздела, и ежедневные — наверх:

```
Чаты        ← мессенджер (счётчик непрочитанных)
Задачи      ← задачи и проекты (счётчик: просрочено + новое в моих задачах)
Знания      ← база знаний (как сейчас)
Академия
Компания    ← справочник сотрудников и оргструктура (для всех)
Аналитика
…
Управление
```

- **Чаты и задачи — разные разделы** (Д.2, Д.4, боль № 13): Битрикс
  смешивал их, сотрудники просят разделить. Связь между ними — ссылками и
  кнопками, а не общим списком.
- **«Компания»** — справочник для всех (8.1–8.3). «Пользователи и роли» в
  «Управлении» остаются местом, где людей заводят и выдают права; здесь —
  только найти человека, посмотреть, кто за что отвечает, написать или
  поставить задачу.
- **«Уведомления» внизу рейки** (над «Управлением», со счётчиком; решение
  владельца 2026-11-07 — в шапке колокольчик незаметен) — центр
  уведомлений (2.26) для всего портала: задачи, упоминания, база знаний,
  Академия, доступы. Чат-сообщения туда не идут — у них свой счётчик на
  «Чатах» (иначе «Уведомления» станут вторым мессенджером).
- **Кнопка «+» в шапке** — «Новая задача» и «Новый чат» из любого места
  портала (горячая клавиша `N` — задача).
- Стартовая страница — решение владельца (п. 13). Предложение: после
  запуска — «Задачи» → «Сроки» (что горит сегодня); «Мой день» (задачи +
  непрочитанные + уведомления на одном экране) — этап 2.

### 3.2. Телефон (PWA)

Портал на телефоне — это и есть «мобильное приложение» (своего нативного
нет и не планируется). В установленном PWA на узком экране вместо рейки —
**нижняя панель**: «Чаты», «Задачи», «Уведомления», «Ещё» (знания,
Академия, компания, аналитика). Экран чата — во всю ширину, назад — к
списку. Проверка вёрстки — 390 / 768 / 1024 / 1440 px, как везде.

### 3.3. «Чаты» (`/chats`)

Раскладка как в Telegram Desktop — её сотрудники называют эталоном:

```
┌──────┬────────────────────┬─────────────────────────────────────┬───────────┐
│Папки │ 🔍 Поиск по всему   │ Название · 12 участников · в сети 3 │ Инфо ▸    │
│      │────────────────────│ 📌 Закреп 2/3 ─────────────────────│           │
│Все 12│ ★ Избранное         │                                     │ Участники │
│Личн 3│ Отдел развития   5  │   сообщения (виртуальный список)    │ Медиа     │
│Групп │ Анна Смирнова    1  │                                     │ Файлы     │
│Проект│ Казань · партнёры @ │                                     │ Ссылки    │
│Задачи│ …                  │ ─────────────────────────────────── │ Настройки │
│Мои…  │                    │ [Поле ввода с форматированием]  ➤   │           │
└──────┴────────────────────┴─────────────────────────────────────┴───────────┘
```

- **Папки** (2.6, боль № 27) — колонка слева: системные «Все»,
  «Личные», «Группы», «Проекты», «Задачи» и свои папки человека (любые
  чаты, порядок перетаскиванием). У папки — число непрочитанных и в
  контекстном меню «Прочитать всё» (Д.3).
- **Чаты задач** — только в папке «Задачи» и не попадают во «Все» (Д.2,
  боль № 13; можно включить в настройках).
- **«Избранное»** (2.7) — чат с собой, всегда первым.
- **Поиск** (2.18, Д.1 — главная боль) — одна строка над списком: по мере
  набора результаты тремя группами «Чаты», «Люди», «Сообщения» (по словам
  во всех моих чатах, с подсветкой и переходом точно к сообщению).
  Фильтры: в чате, от кого, период, «только файлы». Поиск внутри чата —
  та же строка в шапке чата.
- **Шапка чата**: название, участники, кто в сети, кнопки: поиск в чате,
  закреплённые, файлы, «Без звука», «Созвон» (п. 9).
- **Закреплённые** (2.10, боль № 28) — несколько, полоса сверху листает
  их по кругу; закрепляют админы чата (настройка чата).
- **Правая панель** — участники с ролями, вкладки «Медиа», «Файлы»,
  «Ссылки» (2.14, боль № 33), настройки чата.

Сообщение (меню по правой кнопке / долгому нажатию): ответить, цитировать
фрагмент, переслать (в несколько чатов), реакция, закрепить, скопировать
ссылку, изменить / удалить своё, **«Кто прочитал»** (2.13, боль № 32 — по
нажатию, как в Telegram), «Поставить задачу» (этап 2, 1.18).

Поле ввода: форматирование сразу видно (жирный, курсив, подчёркнутый,
зачёркнутый, код, ссылка, список, цитата — боль № 29), упоминание через `@` **и через `+`**
(2.9 — без смены раскладки), эмодзи, вставка скриншота из буфера,
перетаскивание файлов, черновик чата не теряется. Enter — отправить,
Shift+Enter — перенос (на телефоне наоборот).

Типы чатов: личный, группа, «Избранное», чат задачи, чат проекта; этап 2 —
канал (пишут только админы, «Прочитал» — 2.3, 3.3) и чат подразделения с
составом из оргструктуры (2.5).

## 4. Задачи — устройство

### 4.1. Форма (1.1, боль № 1)

Одна форма: сверху быстрые поля (название, исполнитель, срок, проект),
ниже — «Ещё» (соисполнители, наблюдатели, описание, чек-лист, файлы,
срочность, «Требует проверки», напоминание, повтор, шаблон). Настройка
человека «Всегда открывать полностью». Из шаблона — выбором в той же форме.

### 4.2. Роли (1.2, боли № 2, 4)

Постановщик (кто создал; принимает работу), **исполнитель — один**,
соисполнители, наблюдатели. Создатель всегда постановщик — у партнёров и
экспертов ОР это и так их роль. Подсказки в форме объясняют разницу
соисполнителя и наблюдателя (боль № 2). Исполнитель может
**делегировать** (новый исполнитель, прежний становится наблюдателем,
запись в истории) и **сам завершить**, если «Требует проверки» выключено.

| Действие | Постановщик | Исполнитель | Соисполнитель | Наблюдатель |
| --- | --- | --- | --- | --- |
| Видит, пишет в обсуждении | ✓ | ✓ | ✓ | ✓ |
| Чек-листы, файлы | ✓ | ✓ | ✓ | — |
| Срок | ✓ | по правилу срока (4.4) | — | — |
| Участники, проект, описание | ✓ | делегировать | — | — |
| Завершить / принять / вернуть | ✓ | завершить (или «на проверку») | — | — |

Плюс руководители подразделений (над участниками) и право `tasks.admin` —
видят и правят как постановщик.

### 4.3. Несколько исполнителей (1.3, боль № 5)

При выборе нескольких человек форма спрашивает:

- **«Одна общая задача»** (по умолчанию): первый — исполнитель, остальные —
  соисполнители, каждому — пункт чек-листа на его имя. Контекст общий.
- **«Отдельная задача каждому»** — для рассылки на сеть партнёров (Соня).
  Задачи связаны общим `batch_id`; постановщик видит **одну строку-сводку**
  («86 задач: 60 готово, 20 в работе, 6 просрочено», раскрывается), и
  уведомления о них сворачиваются в одно в день (боль № 15).

### 4.4. Срок (1.4, 1.5, боли № 6, 7)

- Дата и время — **в одном окне** (календарь `react-day-picker` + список
  времени). Быстрые: «Сегодня до конца дня», «Завтра», «Конец недели»,
  «Через неделю» — **по рабочим дням** и концу рабочего дня.
- **Производственный календарь России** — таблица `work_calendar` (день →
  рабочий / выходной / праздник / сокращённый). Заполняет сервер раз в год
  из открытых данных (xmlcalendar.ru или API isdayoff.ru), администратор
  может поправить день. Конец рабочего дня — настройка портала (18:00),
  у человека — своя.
- **Часовые пояса**: партнёры в разных городах. Срок хранится как момент
  времени (`timestamptz`), показывается в поясе человека (профиль; по
  умолчанию Москва). «День» в базе портала сейчас считается по Тбилиси
  (корневой CLAUDE.md) — для задач так нельзя, это учитывается с первого
  дня.
- **Правило срока** (у проекта, по умолчанию у портала): исполнитель
  меняет срок «свободно» / «с причиной» (по умолчанию) / «нельзя».
  Причина — в истории и в обсуждении.

### 4.5. Статусы и проверка (1.21, боль № 14)

`Новая → В работе → (На проверке) → Завершена`, плюс «Отложена» и
«Отменена». «Просрочена» — не статус, а признак (срок прошёл, не
завершена). Галочка **«Требует проверки» по умолчанию выключена** —
быстрые задачи не тормозятся; включённая — «Завершить» у исполнителя
превращается в «На проверку», постановщик «Принимает» или «Возвращает» с
комментарием.

### 4.6. Чек-листы, файлы, история

- **Чек-листы** (1.8, боль № 9): несколько списков, один уровень
  вложенности, у пункта — свой исполнитель (меняется), кто и когда
  отметил. Пункты на мне видны в фильтре «Пункты чек-листов на мне».
- **Файлы** (1.9, боль № 10): отдельный блок плиткой с превью и числом в
  заголовке — не теряются; **тяжёлые видео и макеты — докачкой** (TUS,
  п. 10): оборвалась связь — загрузка продолжится.
- **История** (1.22) — отдельная вкладка (кто, что, когда, было → стало,
  причина переноса срока). В обсуждение не подмешивается — Айгуль жалуется,
  что служебные сообщения Битрикса «сбивают историю».

### 4.7. Обсуждение задачи (1.19, боль № 12)

Обсуждение задачи — это **чат задачи** (тот же мессенджер, те же поиск,
упоминания, файлы), но:

- он **не создаётся сам**: появляется при первом сообщении или кнопкой
  «Создать чат»; у задачи на нескольких исполнителей — один чат, не по
  чату на каждого;
- в мессенджере — только в папке «Задачи» (Д.2);
- участники чата = участники задачи (добавили наблюдателя — он в чате);
- служебных сообщений «срок изменён» в нём нет (они в «Истории»), кроме
  смены статуса — одной строкой.

### 4.8. Напоминания и счётчики (1.7, 1.24, боли № 8, 15)

- **Своё напоминание**: «Напомнить мне» — в момент или «за N до срока»;
  ставит сам человек, себе.
- **Автоматически** — только: «вам поставили задачу», «вас упомянули»,
  «задача на проверке / вернули», «срок истекает через час» (исполнителю,
  отключаемо), «просрочена» — **один раз** в момент просрочки (не каждые
  сутки). Постановщику по чужим просрочкам — **одна сводка в день**, а не
  пуш на каждую.
- У задачи — «Уведомления: все / только лично мне / ничего» (Соня: «на
  задачи, где я постановщик на всю сеть, уведомления выключать»).
- Счётчики в рейке и меню: просроченные (как исполнитель), новое в моих
  задачах, ждут моей проверки.

### 4.9. Шаблоны и регулярные (1.15, 1.16, боль № 11)

- **Шаблон**: название, описание, чек-листы, роли, срок «через N рабочих
  дней», проект. Личный / проекта / общий.
- **Регулярная задача** = шаблон + расписание (каждый день / дни недели /
  число месяца / каждые N) или «через N дней после закрытия предыдущей».
  **Не копятся**: следующая создаётся, только когда предыдущая закрыта
  (или по выбору — закрывает прежнюю как «пропущена»). Создаёт фоновый
  цикл сервера (как пуши: раз в минуту), правила повторения — библиотека
  `rrule`.

### 4.10. Проекты (1.36, 1.37, боли № 20, 21)

- Проект = пространство отдела, города или проекта: название, цвет,
  иконка, тип, участники с ролями «владелец / модератор / участник»,
  стадии канбана, правило срока, «Требует проверки» по умолчанию, свой
  чат (в папке «Проекты»).
- **По умолчанию закрытый**; участник добавляется **без подтверждения**
  приглашения. Открытый — виден в каталоге, вступить может любой.
- Состав можно привязать к подразделению оргструктуры («все из отдела
  развития и ниже») — новые сотрудники попадают сами.
- Задачи проекта видят только его участники (боль № 3: «задачи отдела
  должны видеть только сотрудники отдела»).
- Этап 2: диск проекта / города (6.3 — брендбук, материалы).

### 4.11. Задачи подчинённых (1.27)

Руководитель и заместитель подразделения видят задачи, где участник —
кто-то из их подразделения и ниже (из `org_unit_members`, как «руководителям
и ниже» в назначениях ролей). Раздел «Подчинённые»: по людям — сколько в
работе, просрочено, на проверке.

### 4.12. Номера задач

Номер — сквозной (`#1234`, ссылка `/tasks/1234`). Задачи из Битрикса
переносятся **со своими номерами**, новые начинаются выше максимального —
старые «посмотри задачу 4567» в переписке остаются понятными.

## 5. Мессенджер — устройство

### 5.1. Модель (как у Mattermost и Slack — проверенная)

- У чата — счётчик `last_seq`; у сообщения — номер в чате `seq` (1, 2, 3…).
- У участника — `last_read_seq` (до какого прочитал).
- **Непрочитанные** = сообщения чата с `seq > last_read_seq` не от меня.
- **«Кто прочитал»** сообщение N = участники с `last_read_seq ≥ N` —
  отдельных строк «прочитано» на каждое сообщение нет (в чате на 130
  человек это было бы 130 строк на сообщение).
- Упоминания — отдельная лёгкая таблица (человек, чат, `seq`): значок
  «@» у чата, «следующее упоминание», уведомление.
- По `seq` клиент сразу видит пропуски и дозапрашивает их — **«подгружаются
  не все сообщения» (боль № 25) не повторится**.

### 5.2. Что в MVP

Личные и групповые чаты, «Избранное», ответ / цитата / пересылка, правка и
удаление своего («изменено» / «сообщение удалено»), упоминания `@` и `+`
(и `@все` — только админам чата), реакции (быстрый набор + все эмодзи),
форматирование, «прочитано» и «кто прочитал», файлы и вкладки
медиа / файлы / ссылки, несколько закрепов, папки и «Прочитать всё»,
поиск по всем чатам, «без звука», «печатает…», «в сети», ссылка на каждое
сообщение (16.1). История хранится вся, без автоудаления (2.19, боль № 36).

Роли в чате: владелец, админ, участник. Настройки чата: кто добавляет
участников, кто закрепляет (по умолчанию админы), кто пишет (все / только
админы — так из группы получается «канал» до этапа 2).

### 5.3. Ссылки на объекты в сообщениях

Ссылка на задачу, статью базы знаний, курс, сообщение или человека
превращается в «плашку» (у задачи — статус и срок). Упоминание хранится
как ссылка `[Имя](user:<id>)` — так же, как Kate хранит `client:<id>`.

## 7. Права и безопасность

Граница — RLS, как везде (корневой CLAUDE.md, «Модель доступа»). Таблицы
читаются политиками в «быстром» виде — массивом на запрос
(`chat_id = any ((select auth_chat_ids())::uuid[])`, см.
`2026-10-16_zz_rls_initplan_perf.sql`). Запись — через RPC (`security
definer` с проверкой участника), как в Академии.

- **Чат**: читают и пишут участники. Сообщения чатов, из которых человек
  вышел, он больше не видит. Модерация (удалить чужое) — админ чата и
  право `chats.admin`.
- **Задача** видна: участникам; участникам её проекта (закрытого) или
  всем людям портала (открытого); руководителям и заместителям
  подразделений участников (и выше); праву `tasks.admin`.
- **Новые права в каталоге** `access_permissions` (блок «Задачи и чаты»):
  `tasks.admin` (все задачи и проекты), `projects.create`,
  `chats.admin` (модерация), `chats.announce` (`@все` в больших чатах,
  каналы этапа 2), `company.directory_all` (видит всех в справочнике —
  вопрос 3). Выдаются ролями, как остальные права; стартовые роли
  дополняются.
- **Realtime** — только приватные каналы с проверкой в RLS таблицы
  `realtime.messages` (п. 8.1).
- **Файлы** — закрытые бакеты, подписанные ссылки, политики по участию в
  чате / задаче.
- **Уход сотрудника** (8.4): «Заблокировать» в «Пользователях и ролях» —
  его задачи и сообщения остаются; при блокировке — окно «Передать
  открытые задачи» (кому — исполнителем, кому — постановщиком). Вход по
  логину Platrum уже есть; «Отправить доступ письмом» (логин и новый
  пароль на почту — боль № 43) — кнопка в карточке пользователя.

## 8. Реальное время, уведомления, PWA — техника

### 8.1. Транспорт: Supabase Realtime, режим Broadcast

Supabase Realtime уже входит в наш self-hosted Supabase на сервере. У него
три режима; берём **Broadcast из базы** с приватными каналами
([документация Broadcast](https://supabase.com/docs/guides/realtime/broadcast),
[авторизация Broadcast — есть и в self-hosted](https://supabase.com/features/realtime-broadcast-authorization)):

- **Отправка**: браузер вызывает RPC `chat_send` → база проверяет участие,
  выдаёт `seq`, пишет сообщение, триггер вызывает `realtime.send(…)`.
- **Доставка**: у каждой вкладки **одна подписка** — личная тема
  `user:<id>`. Триггер кладёт событие (новое сообщение с превью, правка,
  реакция, прочтение, событие задачи, уведомление) в тему каждого
  участника. Проверка доступа в RLS `realtime.messages` тривиальная
  (`topic = 'user:' || auth.uid()`), лимит «каналов на клиента» не мешает
  (у экспертов ОР — сотни чатов), вкладка получает всё сразу: счётчики
  списка, открытый чат, колокольчик.
- **«Печатает…»** — эфемерная тема `chat:<id>` только у открытого чата
  (без записи в базу), доступ — проверкой участника.
- **Почему не «Postgres Changes»**: там Realtime проверяет RLS каждой
  строки для каждого подписчика — при сотнях людей это узкое место
  (Supabase сама советует Broadcast для масштаба).
- **Надёжность**: Realtime доставляет «не больше одного раза». При
  переподключении, возврате во вкладку и пропуске `seq` клиент
  дозапрашивает «что изменилось с …» обычным запросом. Источник правды —
  база и кэш React Query; события только обновляют кэш.
- **Объём**: сотни человек, десятки тысяч сообщений в день → сотни тысяч
  строк в `realtime.messages` в день (Supabase хранит их разделами по
  дням и чистит сама) — для Postgres немного. Если вырастем — рассылку по
  участникам переносим из триггера в фоновый цикл сервера, интерфейс не
  меняется.
- **«В сети»** (2.28) — пульс раз в минуту из открытой вкладки в
  `portal_presence` (как `an_presence`), а не общий канал Presence на
  500 человек (там каждое изменение рассылается всем).

### 8.2. Уведомления

Одна функция в базе `notify(кому, что, объект, ссылка, ключ группировки)`
решает по настройкам человека: лента / пуш / почта.

- **Не пушить, если человек сейчас в портале** (вкладка активна по
  пульсу) — он и так видит.
- **Группировка**: несколько сообщений в чате за минуту — один пуш «3
  новых сообщения»; на телефоне уведомления одного чата заменяют друг
  друга (`tag` чата), а не копятся.
- **Умолчания**: личные сообщения, упоминания, «вам поставили задачу»,
  «на проверку / вернули» — пуш; большие группы (больше 20 человек) —
  пуш только на упоминания; остальное — счётчики.
- Значок на иконке приложения — число непрочитанного (Badging API).
- Почтой — этап 2: сводка непрочитанных упоминаний, если человек не
  заходил N часов.

Отправка уже есть (без сторонних сервисов, RFC 8291 / 8292,
`lib/push/web-push.server.ts`) — работала только для клиентских

## 9. Готовые решения: что берём, что нет

### 9.1. Готовый мессенджер целиком — не берём

| Вариант | Плюсы | Почему нет |
| --- | --- | --- |
| Mattermost, Rocket.Chat, Zulip, Matrix (Element) — свой сервер | готовы треды, поиск, звонки плагинами, приложения | отдельные учётные записи и вход (наш вход — код из письма и логин Platrum), своя модель прав без нашей оргструктуры и ролей, задачи с чатом не связать, другой интерфейс в iframe, ещё один тяжёлый сервис на том же сервере (Rocket.Chat — MongoDB, Matrix Synapse и Zulip — много памяти), пуши мобильных приложений — через шлюзы производителя за рубежом |
| SaaS-чаты (Stream, Sendbird, CometChat, PubNub) | быстро встроить | данные сотрудников за рубежом (152-ФЗ), оплата и санкционные риски |

Наша сильная сторона — всё в одной базе: задачи, чаты, люди, права, база
знаний и поиск по всему этому. Отдельный мессенджер её убивает.

### 9.2. Берём готовые кирпичи под наш стек

| Задача | Берём | Почему |
| --- | --- | --- |
| Транспорт | **Supabase Realtime** (Broadcast + авторизация) | уже на сервере, тот же вход и RLS |
| Заготовка чата | **Supabase UI «Realtime Chat»** (реестр shadcn, есть вариант для TanStack) — [описание](https://supabase.com/library/docs/tanstack/realtime-chat.md) | как образец хуков (прокрутка, подписка); сам по себе простой — без истории, папок и виртуализации, поэтому не основа, а старт |
| Длинная лента сообщений | **virtua** (MIT, ~3 КБ; `shift` для подгрузки старых сверху без прыжка) — взята в 1.62 | тысячи сообщений без тормозов (боль № 25) |
| Поле ввода | **TipTap** (MIT) + расширения Mention (`@` и `+`), Link, Placeholder, Markdown | ProseMirror / TipTap уже внутри BlockNote — тот же движок, версии согласовать; форматирование видно сразу (боль № 29) |
| Описание задачи, шаблоны | **BlockNote** — редактор базы знаний | тот же редактор, картинки, видео, файлы |
| Показ сообщений | `react-markdown` + `remark-gfm` (уже есть) | как у Kate |
| Эмодзи и реакции | **frimousse** (MIT, от Liveblocks, под shadcn) | лёгкий, без своих стилей |
| Загрузка больших файлов | **TUS** (`tus-js-client`, взят в 1.62) в Storage — докачка [есть и в self-hosted](https://supabase.com/docs/guides/storage/uploads/resumable-uploads) | тяжёлые видео и макеты (боль № 10) |
| Перетаскивание (канбан, папки) | `@atlaskit/pragmatic-drag-and-drop` (уже есть) | одна библиотека на портал |
| Даты и время | `date-fns`, `react-day-picker` (уже есть) | — |
| Повторы | **rrule** | стандарт RRULE, следующий запуск |
| Производственный календарь | данные xmlcalendar.ru / API isdayoff.ru | бесплатно, раз в год |
| Поиск | Postgres FTS `russian` + начало слова (как `kb_search`), `pg_trgm` для опечаток | уже умеем; если на истории Битрикса качество слабое — PGroonga (есть в образе Postgres Supabase) |
| Звонки (этап 2) | **LiveKit** (Apache-2.0, сервер + `@livekit/components-react` с готовой видеоконференцией, демонстрацией экрана, записью) — [репозиторий](https://github.com/livekit/livekit) | своё вместо Zoom / Телемоста (2.20–2.25); отдельный небольшой сервер (UDP, TURN). Запасной — Jitsi Meet по ссылке |
| Календарь (этап 2) | **FullCalendar 6** — только свободные плагины MIT (день и неделя по часам, месяц, список, перетаскивание); взят 2026-11-08 | общие календари (4.2) |

UX подсматриваем (не встраиваем): Telegram (ориентир сотрудников —
папки, поиск, закрепы, «кто прочитал»), Mattermost (модель прочтения),

## 12. Риски

- **Пуши в России**: доставка через службы Google / Apple — проверить на

- **Часовые пояса**: портал считает «день» по Тбилиси; задачи и
  уведомления — по поясу человека, иначе «до конца дня» в Новосибирске

- Микрофон — вместо «Отправить», пока поле пустое и нет файлов (при правке
  сообщения — «Сохранить»). Держать — запись (красная точка, время, живая
  волна), отпустить — отправить, увести палец влево — отмена, вверх —
  «без рук»: запись идёт, кнопка становится «Отправить», рядом «Отмена».
  Короче 0,7 с — не отправляется (подсказка «удерживайте»), дольше
  15 минут — уходит сама; Esc — отмена.
- Звук пишет браузер (webm/opus, у Safari — mp4/aac, 32 кбит/с ≈ 240 КБ
  в минуту), файл — в `chat-files` с докачкой; пока грузится — плашка
  «Голосовое 0:12 · отправка…» над полем (текст при этом можно писать и
  отправлять), загрузилось — уходит отдельным сообщением.
- В сообщении — плеер: «Слушать / Пауза», волна (сыгранное — цветом чата,
  нажать или протянуть — перемотка), время, скорость 1× / 1,5× / 2×
  (помнится). Одновременно играет одно голосовое. В сведениях чата —
  во вкладке «Файлы», тоже плеером. Превью в списке чатов, пуше и письме —
  «Голосовое сообщение (0:12)».
- Эмодзи — кнопка в поле справа (и на телефоне): весь набор Unicode до
  версии 15 (~1870, без оттенков кожи), поиск по-русски и по-английски
  («огонь», «ржач», «lol», «флаг россия»), разделы со значками, «Недавние».
- Не сделано (по брифу 2.15, не просили): личная настройка «не принимать
  голосовые».
