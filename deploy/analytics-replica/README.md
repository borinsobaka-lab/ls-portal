# Агент синхронизации старого портала аналитики

Старый портал аналитики Lady Stretch продолжает работать как прежде, а его
данные раз в две минуты копируются в раздел «Аналитика» портала
(ANALYTICS_PLAN.md, §3: оба портала работают одновременно). Копирует агент
`agent.py` — его ставят на сервер **старого** портала.

- Только читает: базы SQLite открываются на чтение (`mode=ro`), служба видит
  файловую систему только на чтение, кроме своей папки состояния. Код,
  службы и данные старого портала не меняются.
- Без паролей, токенов сессий и ключей в открытом виде.
- Python 3 из системы, без сторонних пакетов — как весь код старого портала.

## Что копируется сейчас

Модуль `core` (база `portal.sqlite3`) → таблицы `an_legacy_*` портала:
пользователи (без паролей), выданные отчёты, города, карточки и условия
партнёров, студии FitBase партнёров, сессии (без токенов), активное время,
журнал действий. Остальные модули (1С, отзывы, VK Ads, amoCRM, Авито,
FitBase, квиз, диалоги VK, контент) добавляются по этапам плана.

## Установка

1. В Coolify у портала задать `ANALYTICS_REPLICA_SECRET` — случайная строка
   от 32 символов (например, `openssl rand -hex 32`), перезапустить портал.
   Проверить: «Аналитика» → «Синхронизация со старым порталом» — блок
   «Агент на старом сервере».
2. На компьютере с Windows, откуда есть SSH-доступ к серверу старого
   портала, запустить **«Установить синхронизацию.bat»** из этой папки.
   Батник спросит адрес сервера (`root@…`), скопирует файлы и запустит
   установщик. Установщик спросит адрес портала (`https://portal.…`) и тот
   же ключ, проверит связь и включит таймер.
3. На странице «Синхронизация со старым порталом» появится «Агент на
   связи» и число строк по таблицам.

Повторная установка обновляет агента и предлагает оставить прежние
настройки.

## Проверка и удаление

- **«Проверить синхронизацию.bat»** — что и когда отправлено, таймер и
  последние строки журнала службы. На сервере то же:
  `lady-analytics-replica --status`, `journalctl -u lady-analytics-replica -n 50`.
- `lady-analytics-replica --reset <таблица>` (или `all`) — забыть, что
  отправлено, и отправить заново целиком.
- **«Убрать синхронизацию.bat»** — выключить таймер и удалить агента.
  Скопированные данные в портале остаются.

## Как устроено

- Раз в 2 минуты (`lady-analytics-replica.timer`) агент сравнивает таблицы с
  тем, что уже отправлено (`/var/lib/lady-analytics-replica/state.sqlite3`):
  новые и изменённые строки и ключи удалённых (таблицы `diff`), новые строки
  журналов по id (`append`).
- Отправка — `POST <портал>/api/analytics/replica`, gzip, пачки до 5000
  строк, подпись HMAC-SHA256 ключом `ANALYTICS_REPLICA_SECRET`
  (`apps/admin/src/lib/analytics/server/replica.server.ts`). Отправленное
  отмечается только после ответа «принято» — сбой связи ничего не теряет.
- В конце каждого запуска — отметка «агент на связи» с итогом по таблицам.

## Новый модуль (для разработчика аналитики)

1. Миграция модуля: таблица-получатель `an_<модуль>_…` с теми же колонками,
   что у старого портала, и строка в `an_replica_targets` (ключ upsert).
2. Источник в `SOURCES` в `agent.py`: модуль, таблица-получатель, путь к
   базе (ключ настройки, например `ONEC_DB`), таблица, колонки, ключ, режим.
3. Новый путь к базе — значение по умолчанию в `DEFAULTS`.
4. Переустановить агента батником (настройки сохраняются; `MODULES` в
   настройках не задан — агент отправляет все модули).
