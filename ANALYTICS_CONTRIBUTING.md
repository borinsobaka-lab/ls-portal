# Как вести «Аналитику»: инструкция по шагам

Для разработчика раздела «Аналитика» портала LadyFitPro. Программировать не
нужно: вы пишете задачу обычными словами, код пишет Claude — ИИ-программист в
браузере. Вы проверяете результат на своём тестовом портале и отправляете
правку владельцу. На рабочий портал она попадёт, только когда владелец её
примет.

## Как это устроено

Есть три места:

| Что                               | Адрес                                    | Кто меняет                     |
| --------------------------------- | ---------------------------------------- | ------------------------------ |
| Рабочий портал                    | https://portal.ladyfitpro.ru             | только владелец                |
| Ваша копия кода портала на GitHub | `https://github.com/ВАШ_ЛОГИН/ls-portal` | вы и ваш Claude                |
| Ваш тестовый портал («стенд»)     | https://analytics.ladyfitpro.ru          | обновляется сам из вашей копии |

Каждая задача проходит один путь:

1. Вы пишете Claude, что сделать.
2. Claude делает правку в вашей копии.
3. Вы пишете Claude «выложи на стенд». Через 5–10 минут правка на тестовом
   портале.
4. Вы проверяете. Не так — пишете Claude, что поправить, и снова «выложи на
   стенд».
5. Всё хорошо — отправляете правку владельцу. Он её принимает, и она
   появляется на рабочем портале.

Тестовый портал можно ломать сколько угодно: рабочий от него не зависит.

## Что понадобится

- Компьютер с браузером (Chrome, Edge, Яндекс Браузер или Safari).
- Почта, на которую вы будете получать письма.
- Платная подписка Claude (Pro или Max) — без неё Claude Code не работает.
  Оформляется на https://claude.ai.

## Часть 1. Один раз, в первый день

Займёт 10–15 минут. После неё владелец доделает тестовый портал.

### Шаг 1. Зарегистрироваться на GitHub

GitHub — сайт, где хранится код портала.

1. Откройте https://github.com/signup.
2. Введите почту, придумайте пароль и имя пользователя (логин) — латиницей,
   например `ivan-analytics`.
3. GitHub попросит решить задачку «я не робот» и пришлёт на почту код —
   введите его.
4. Запишите свой логин. Дальше в инструкции он — `ВАШ_ЛОГИН`.

Уже есть аккаунт на GitHub — просто войдите в него.

### Шаг 2. Сделать свою копию портала

1. Откройте https://github.com/borinsobaka-lab/ls-portal.
2. Справа вверху нажмите кнопку **Fork**.
3. Откроется страница «Create a new fork». Ничего не меняйте и нажмите
   зелёную кнопку **Create fork**.
4. Через несколько секунд откроется ваша копия. Сверху слева будет написано
   `ВАШ_ЛОГИН/ls-portal`, а под этим — «forked from
   borinsobaka-lab/ls-portal». Сохраните адрес этой страницы в закладки.

### Шаг 3. Создать ветку для тестового портала

Ветка — отдельная версия кода внутри вашей копии. Из ветки `stand`
собирается тестовый портал.

1. На странице своей копии, над списком файлов слева, нажмите кнопку
   **main**.
2. В появившемся поле напечатайте `stand` — маленькими латинскими буквами,
   без пробелов.
3. Ниже появится строка **Create branch: stand from main** — нажмите её.
4. Проверка: кнопка теперь называется **stand**, а список файлов тот же
   (папки `apps`, `db`, `deploy` и другие).

### Шаг 4. Написать владельцу

Отправьте владельцу портала:

- свой логин на GitHub;
- почту, имя и фамилию — на эту почту будет приходить код для входа на
  тестовый портал.

Дальше ждите сообщения от владельца: он настроит тестовый портал и пришлёт
**адрес** и **секрет** для автообновления (две длинные строки).

## Часть 2. Один раз, когда владелец всё настроил

### Шаг 5. Включить автообновление тестового портала

Это нужно, чтобы тестовый портал сам обновлялся, когда Claude выкладывает
правку.

1. Откройте свою копию на GitHub и нажмите вкладку **Settings** (шестерёнка
   справа в верхнем ряду вкладок).
2. В меню слева выберите **Webhooks**, затем кнопку **Add webhook**. GitHub
   может попросить ещё раз ввести пароль.
3. Заполните форму:
   - **Payload URL** — вставьте адрес от владельца;
   - **Content type** — выберите `application/json`;
   - **Secret** — вставьте секрет от владельца;
   - ниже оставьте отмеченным **Just the push event** и галочку **Active**.
4. Нажмите **Add webhook**.

Адрес и секрет никому не пересылайте и никуда, кроме этой формы, не
вставляйте.

### Шаг 6. Подключить Claude к своей копии

1. Откройте https://claude.ai/code и войдите в свой аккаунт Claude.
2. Claude предложит подключить GitHub — нажмите **Connect GitHub** и войдите
   в GitHub.
3. GitHub спросит, к каким репозиториям дать доступ. Выберите **Only select
   repositories**, отметьте `ВАШ_ЛОГИН/ls-portal` и нажмите **Install**.
4. Проверка: в Claude Code при создании нового сеанса в списке
   репозиториев есть `ВАШ_ЛОГИН/ls-portal`.

### Шаг 7. Войти на тестовый портал

1. Откройте https://analytics.ladyfitpro.ru. Сверху — оранжевая полоса,
   внизу — надпись «Тестовый стенд — не рабочий портал». Так тестовый
   портал отличается от рабочего.
2. Выберите вкладку **Почта**, введите свою почту и нажмите **Получить код
   для входа**.
3. Введите 6 цифр из письма. Письма нет — проверьте папку «Спам».

На тестовом портале вы — главный администратор. Данных там сначала нет:
выгрузки 1С и ключи FitBase, amoCRM, VK, Авито вы загружаете сами, когда они
нужны для проверки.

Готово. Сделайте первую задачу по разделу ниже — например, для пробы:
_«на главной странице Аналитики добавь в подсказку слово «тест»»_. В
описании правки для владельца напишите «Пробный круг, не сливать».

## Каждая задача

### А. Обновить свою копию

Владелец тоже меняет портал, поэтому перед каждой задачей копию нужно
обновлять.

1. Откройте свою копию на GitHub (ветка **main**).
2. Над списком файлов нажмите **Sync fork**, затем **Update branch**.
   Написано «This branch is up to date» — обновлять нечего.

### Б. Дать задачу Claude

1. Откройте https://claude.ai/code и начните **новый сеанс** с репозиторием
   `ВАШ_ЛОГИН/ls-portal`. Одна задача — один сеанс.
2. Первое сообщение начните так: _«Я разработчик аналитики, работаю в
   форке. Задача: …»_ — и опишите, что нужно, как объяснили бы коллеге:
   какой отчёт, какие цифры, как считать, как должно выглядеть.
3. Claude сам прочитает правила проекта, сделает правку и проверит её.
   Если он задаёт вопросы — отвечайте.

### В. Проверить на тестовом портале

1. Напишите Claude: _«Выложи на стенд»_.
2. Через 5–10 минут обновите страницу https://analytics.ladyfitpro.ru и
   проверьте правку.
3. Что-то не так — опишите Claude в том же сеансе, что видите, и снова
   попросите выложить на стенд.

Тестовый портал один: выложили новую задачу — прежняя, ещё не принятая
владельцем, с него пропадёт.

### Г. Отправить правку владельцу

1. Напишите Claude: _«Расскажи, что изменилось и что проверено. Напиши текст
   для описания Pull Request»_. Pull Request — это запрос владельцу
   «примите мою правку».
2. Откройте свою копию на GitHub. Сверху будет жёлтая полоса с веткой
   `claude/…` — нажмите **Compare & pull request**. Полосы нет — нажмите
   **Contribute**, затем **Open pull request**.
3. Проверьте строку вверху страницы. Слева должно быть
   `base repository: borinsobaka-lab/ls-portal` и `base: main`, справа —
   ваша копия и ветка, которая начинается с `claude/` (**не** `stand`).
4. Заголовок — коротко, что сделано. В описание вставьте текст от Claude.
5. Нажмите **Create pull request** и пришлите ссылку владельцу.

Внизу страницы запроса появятся две автоматические проверки:

- **«Аналитика — пути»** красная — правка задела что-то за пределами
  раздела. Вернитесь в тот же сеанс Claude и напишите: _«Проверка путей
  красная, исправь»_.
- **«Аналитика — проверки»** красная — в коде ошибка. Нажмите **Details**,
  скопируйте текст ошибки в тот же сеанс Claude и попросите исправить.

Исправления Claude сами попадают в тот же запрос — новый открывать не нужно.
Когда владелец примет запрос, правка через несколько минут появится на
рабочем портале.

## Если что-то пошло не так

| Что случилось                                          | Что делать                                                                                                                                            |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Правка не появилась на тестовом портале через 15 минут | Копия на GitHub → **Settings** → **Webhooks** → ваш веб-хук → вкладка **Recent Deliveries**. Сделайте скриншот последней строки и пришлите владельцу. |
| Тестовый портал не открывается или показывает ошибку   | Напишите владельцу, что видите на экране. Рабочий портал от этого не пострадал.                                                                       |
| Нет кнопки **Sync fork**                               | Вы не на главной странице своей копии или не в ветке **main**. Откройте `https://github.com/ВАШ_ЛОГИН/ls-portal`.                                     |
| В Claude Code нет вашего репозитория                   | Повторите шаг 6: GitHub → Settings (вашего профиля) → Applications → Claude → Configure → добавьте `ls-portal`.                                       |
| Не приходит код для входа                              | Проверьте «Спам». Не помогло — напишите владельцу.                                                                                                    |

## Правила

- Меняется только раздел «Аналитика». Claude это знает и сам не полезет в
  другие разделы. Нужно что-то за пределами раздела (новый пункт меню,
  права доступа, новая библиотека) — Claude напишет это в описании запроса,
  и владелец сделает это сам.
- Не пишите Claude и не кладите в код настоящие данные клиентов, пароли и
  ключи: код портала открыт всем. Ключи сервисов вводятся только в формы на
  тестовом портале.
- **На тестовом портале не включайте отправку наружу с настоящими
  адресатами.** Задачи с пометкой «Внешнее действие» (Telegram партнёрам,
  Google-таблицы, публикации VK) включайте только со своими тестовыми
  чатами, таблицами и группами — иначе партнёры получат дубли сообщений.
- Сборщик оснований FitBase на тестовом портале — только под другой
  учётной записью FitBase, не той, что у рабочего портала.
- Нужна чистая база на тестовом портале — попросите владельца её сбросить.
  Всё, что вы туда загрузили, сотрётся.

## Словарик

- **GitHub** — сайт, где хранится код.
- **Репозиторий** — папка с кодом портала на GitHub.
- **Форк (копия)** — ваша личная копия репозитория. Её меняете вы, основной
  код она не трогает.
- **Ветка** — отдельная версия кода внутри копии. `main` — основная, `stand`
  — для тестового портала, `claude/…` — ветки, которые Claude заводит под
  задачи.
- **Стенд** — ваш тестовый портал https://analytics.ladyfitpro.ru.
- **Веб-хук** — сигнал от GitHub тестовому порталу «код обновился,
  пересоберись».
- **Pull Request** — запрос владельцу «примите мою правку в рабочий портал».
