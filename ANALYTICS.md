# Аналитика — отчёты сети

Статус: **сделано 2026-10-26** (раздел рейки «Аналитика», в самом низу
списка разделов). Схема — `db/migrations/2026-10-26_zzz_analytics_network.sql`
(заменила первую версию `2026-10-26_zz_analytics.sql`), тесты базы —
`db/analytics.test.ts`, код админки — `apps/admin/src/lib/analytics/`
(расчёты, разбор выгрузок, загрузка + тесты), `components/analytics/`,
`routes/_authenticated/analytics/`.

## Зачем

Lady Stretch параллельно делала свой портал аналитики
(analytics.lady-stretching.ru: Python + SQLite на VPS Selectel, свои
пользователи и права), чтобы показывать партнёрам статистику студий,
которые ведут учёт в 1С, FitBase, АДИС, Мобифитнесе. С переходом сети на
наш портал он не нужен.

**Решение владельца 2026-10-26** (уточнение к первой версии того же дня):
вся бизнес-логика их портала — у нас, но **без привязки к нашим клубам,
продажам и расписанию**. Раздел — для студий сети, которые ещё сидят на
своих учётных системах: данные приходят выгрузками, портал считает отчёты и
показывает их собственникам (партнёрам). У наших клубов свой дашборд
(«Дашборд» в рейке) — его развиваем вместе с расписанием и продажами; когда
студия переедет на нашу CRM, её отчёты будут там. Первая версия (отчёты по
нашим продажам, раздел клуба `club.analytics`) удалена.

## Что было у Lady Stretch (по их документации, архив владельца 2026-10-26)

1. **Аналитика 1С** (выгрузки 1С в Excel → локальная программа обработки →
   снимок SQLite с дневными агрегатами → загрузка на портал):
   - **Выручка** — города → студии, текущий месяц по календарным неделям
     (пн–вс, обрезаны месяцем), факт, прогноз (факт / прошедшие дни × дней в
     месяце), полгода истории, фильтр «открытые / закрытые», поиск,
     «точка 0» (месячная цель города);
   - **Продажи абонементов** — продажи, новые / повторные, оплаты новых и
     повторных, средние чеки, динамика к тем же датам прошлого месяца и
     прошлого года, графики за 9 месяцев, номенклатуры;
   - **Занятия и посещаемость** — занятия, записи, посещения, средние на
     занятии, доходимость, сравнения, направления;
   - **Воронка пробного** — записи → посещения → покупка в день пробного →
     покупка в пределах 14 дней, виды пробных;

     пробных): город → студия → номенклатура;

     прогноз, точка 0, продажи по сегментам, «что покупают» (все / новые /
     продления), направления, пробные, таблица студий;
   - **Топ-10 городов** за месяц — покупка в день пробного, за 14 дней,
     продления без возвращённых, возвращённые.
2. **FitBase** — те же отчёты (выручка, продажи, посещаемость, воронка,
   «Мой город · FitBase») для студий на FitBase: ночная загрузка по API,
   своя SQLite.
3. **Маркетинг** — amoCRM (лиды из воронок новых лидов, квалификация по
   «Основанию для закрытия», записались / пришли / купили, когорта по
   месяцу создания сделки, срез на 1-е число и «догрев»), VK Ads (расходы

4. **Портал** — admin / viewer, партнёр = viewer с городами, журнал

5. **Inbox VK** (сообщения сообществ) — отдельный сервис, к аналитике не

### Загрузка выгрузок

Четыре вида данных (у Lady Stretch — отчёты 1С; другие системы — так же,
любой табличной выгрузкой с нужными колонками):

- **Выручка** — движение денег: дата, студия, приход, расход (статья —
  необязательно). Выручка = приход − расход.
- **Продажи** — дата (время), студия, код клиента, номенклатура (код и
  название), стоимость, оплата.
- **Занятия** — дата, студия, направление, занятий, записано, посетило.
- **Посещения с членством** — дата, студия, код клиента, членство, статус
  («Прибыл» / «Не прибыл») — для воронки пробных.

Разбор (`lib/analytics/import.ts` + тест): строка заголовков и колонки
находятся сами по синонимам (можно поправить вручную), иерархический отчёт
1С подходит — дата и студия из строк-групп протягиваются вниз, подытоги
групп пропускаются. Коды клиентов браузер заменяет хэшем SHA-256 (с
системой) до отправки — имён, телефонов и самих кодов в базе нет. Загрузка
идёт пачками по 2000 строк (`an_import_start` → `an_import_rows` →
`an_import_finish`); пока не завершена, отчёты её не видят, сбой — загрузка
удаляется. Новая загрузка **заменяет** данные того же вида у своих студий за
свой период (повторная выгрузка за месяц не задваивает). Новые студии и
номенклатура заводятся сами.

FitBase, АДИС, Мобифитнес — пока так же, файлами. Коннектор FitBase по API
(ночная загрузка, как у Lady Stretch) — следующий шаг.

### Правила расчёта (как у Lady Stretch)

- **Выручка** — приход − расход; сегодняшний день не входит ни в факт, ни
  в прогноз. **Прогноз** = факт / прошедшие полные дни × дней в месяце
  (только текущий месяц). Недели — пн–вс, обрезаны границами месяца.
- **Точка 0** — на город; «Прогноз − точка 0» — у города и сети (сумма
  точек 0 городов, если отчёт охватывает города целиком).
- **Продажи абонементов** — строки номенклатуры категории «Абонемент» с
  оплатой > 0. **Новая** — самая ранняя оплаченная покупка абонемента
  клиентом за всю загруженную историю (по хэшу кода); **повторная** — все
  следующие: перерыв больше 60 дней от прошлой покупки — «возвращённый»,
  иначе «продление» (у Lady Stretch деления не было — наше правило для
  рейтинга). Без кода клиента — «не определено». **Средний чек** — оплаты /
  число продаж.
- **Занятия** — строка считается, только если занятий, записанных и
  посетивших > 0; средние и доходимость (посетило / записано) — из итоговых
  сумм.
- **Пробные** — посещение с членством, название которого есть в
  номенклатуре категории «Пробное занятие»; пришёл — «Прибыл» (не «Не
  прибыл»); купил — оплаченный абонемент того же клиента в день пробного
  или в следующие 13 дней (покупка относится к последнему пробному в
  окне). «Окно открыто» — 14 дней ещё не прошли.
- **Нулевая номенклатура** — продажи со стоимостью 0 или пустой, кроме
  пробных.
- Доли и средние — из итоговых числителя и знаменателя; нет знаменателя —
  «—». Изменение к прошлому периоду — относительное, %. Суммы — в рублях.

### Доступ

Сетевые права каталога «Пользователей и ролей» (блок «Разделы»):

- `analytics.view` «Аналитика сети: все клубы» — отчёты по всем студиям
  (владелец франшизы);
- `analytics.clubs` «Аналитика сети: свои клубы» (2026-10-27, копия Lady
  Stretch) — право «в клубе»: клубы выбираются при назначении роли (все,
  клубы бренда, выбранные), отчёты — по студиям, связанным с этими клубами
  (`an_studios.club_id`, поле «Клуб портала» в «Студиях сети»). Клубы
  заводятся в «Оргструктуре» → «Сеть клубов». Клубы человека считаются из
  его действующих назначений в момент запроса (`an_club_ids`), пересчёт
  прав их не сворачивает; к ним добавляются клубы, где он собственник
  («Сеть клубов», `studio_owners`, 2026-10-27). Стартовая роль — «Владелец клуба — аналитика».
  Схема — `db/migrations/2026-10-27_analytics_clubs.sql`;
- `analytics.cities` «Аналитика сети: свои города» — партнёр: только города
  из «Доступа партнёров» (`an_user_cities`); без городов — пусто;
- `analytics.manage` «Аналитика сети: загрузка и справочники».

Стартовые роли: «Аналитика сети» (`analytics.view`) и «Партнёр — аналитика»
(`analytics.cities`). У людей вне модели прав — владелец клуба (как в
прочих сетевых правах). Граница — база: таблицы фактов закрыты, отчёты —
RPC `an_*_report` (security definer, студии — `auth_an_studio_ids()`),
отдают только агрегаты массивами в jsonb (без лимита PostgREST).

### Устройство

- База: `an_studios`, `an_city_targets`, `an_nomenclature`, `an_imports`,
  факты `an_revenue` / `an_sales` / `an_classes` / `an_visits` (удаление
  загрузки — каскадом), `an_user_cities`; RPC `an_access`, `an_scope`,
  `an_revenue_report` / `an_sales_report` / `an_classes_report` /
  `an_trials_report` (корзина день или месяц), `an_zero_report`,
  справочники `an_studios_list`, `an_studio_save`, `an_nomenclature_set`,
  `an_city_target_save`, `an_partners_list`, `an_partner_cities_save`.
- Админка: запросы — `lib/analytics/data.ts` (ключи `["analytics", …]`),
  расчёты — `lib/analytics/logic.ts`, разбор — `import.ts`, отправка —
  `upload.ts` (xlsx читает `read-excel-file`, грузится только со страницей
  загрузки), подписи — `labels.ts` (их же берут скелетоны), каркас и
  фильтры — `components/analytics/analytics-shell.tsx` +
  `hooks/use-analytics-filters.ts`, дерево «Город → студия» —
  `components/analytics/city-tree.tsx`.
